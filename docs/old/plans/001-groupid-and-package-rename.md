## Why this matters

`docs/MOHS-DOCUMENTO-MESTRE.md` (§1 and §8, ADR 0001) already decided the
project's identity: org `mohs-io`, groupId `io.mohs`, single artifact
`io.mohs:mohs`, packages `io.mohs.*`. The actual bootstrap generated by
Spring Initializr never got updated to match — it still uses the
placeholder `io.github.robsonkades` groupId and package. This is the
cheapest point in the project's life to fix it: right now it's one `../../../pom.xml`
line and two Java files. Every class, test, and config key added under the
wrong package (including the M0 skeleton in plan 002) makes the eventual
rename touch more files. Maven coordinates in particular become effectively
frozen the moment anything depends on them externally.

## Steps

### Step 1: Update the Maven groupId

In `../../../pom.xml`, change line 11 from:
```xml
<groupId>io.github.robsonkades</groupId>
```
to:
```xml
<groupId>io.mohs</groupId>
```
Leave `<artifactId>mohs</artifactId>` (line 12) unchanged — it already
matches the decided `io.mohs:mohs` coordinate.

**Verify**: no automated check yet — the next steps confirm this via the
full build. Just re-read the line to confirm the edit landed correctly.

### Step 2: Move the main source file to the new package path

Move `src/main/java/io/github/robsonkades/mohs/MohsApplication.java` to
`src/main/java/io/mohs/MohsApplication.java` (create the `src/main/java/io/mohs/`
directory as part of the move; use `git mv` since the file is already tracked
in the index — `git status` shows it under "Changes to be committed").

Edit the moved file's package declaration from:
```java
package io.github.robsonkades.mohs;
```
to:
```java
package io.mohs;
```

Then remove the now-empty `src/main/java/io/github/` directory tree.

### Step 3: Move the test source file to the new package path

Move `src/test/java/io/github/robsonkades/mohs/MohsApplicationTests.java` to
`src/test/java/io/mohs/MohsApplicationTests.java` the same way, updating its
package declaration from `io.github.robsonkades.mohs` to `io.mohs`.

Then remove the now-empty `src/test/java/io/github/` directory tree.

**Verify**: `find src -iname "*.java"` (or equivalent) shows exactly two
files: `src/main/java/io/mohs/MohsApplication.java` and
`src/test/java/io/mohs/MohsApplicationTests.java`. No `io/github` path
remains anywhere under `src/`.

### Step 4: Build and test

Run:
```
./mvnw compile
./mvnw test
```
Both must succeed. The test output should show
`io.mohs.MohsApplicationTests` (not the old package) starting the Spring
context and the `contextLoads` test passing.

### Step 5: Confirm no stale references remain

Run:
```
grep -rn "io.github.robsonkades" pom.xml src/
```
Expected: no matches (empty output / exit with no results).

## Test plan

No new tests are introduced by this plan — it's a pure rename. The existing
`contextLoads()` test in the relocated `MohsApplicationTests.java` is the
regression check: if the package move broke Spring's component scanning or
left a stale reference, that test will fail to start the application
context.
